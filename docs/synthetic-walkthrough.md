# Synthetic walkthrough — GovernedGraph in practice

This is a **recording-ready storyboard**, not a video of a validated live system. The existing sample uses synthetic pension-transition members and the approved Azure-hosted presenter. No local fallback, real customer data, deployment secrets or fabricated screenshots are required.

## Suggested 5-minute recording

| Segment | Demonstrate | Narration |
|---|---|---|
| 0:00–0:30 | [Overview diagram](diagrams/overview.png) | Facts come from deterministic systems; AI explains within approved boundaries; two feedback loops improve the approved experience. |
| 0:30–1:30 | Synthetic member starts chat or voice using the [presenter runbook](../examples/pension_wtp/docs/demo-runbook.md) | The host authenticates, screens, routes and selects an approved strategy. The model never invents the official figure. |
| 1:30–2:15 | Trace and checked answer | Highlight the authoritative read through the release gate, approved Search passages, numeric fidelity, signed ranking and immutable audit before delivery. |
| 2:15–3:00 | Aggregate learning evidence | Outcome aggregates can reorder existing approved explanations after fairness veto and bounded governance. Raw conversation text does not enter ranking. |
| 3:00–4:05 | Deliberately synthetic declined examples and nightly gap-review output | Five eligible declines from three journeys can trigger an inert proposal. The tool-free Foundry agent drafts ideas, not policy changes. |
| 4:05–4:45 | Administration console owner decision | Show verified source for new content, an approved-pattern explanation style, deferral/rejection and the journal. An approved idea is not yet live. |
| 4:45–5:00 | Separate signed catalogue/content publication, then measurement | A published change is monitored for outcomes and safety against a governed baseline; publication is not proof of benefit. |

## Recording controls

Record only after the exact synthetic Azure deployment has passed the necessary proof, and capture the timestamp, commit, model/agent versions, deployment scope and permitted identities in a **private** evidence receipt. Do not expose real endpoint URLs, access tokens, people, chat transcripts, member references or administrator secrets.

If the scheduled batch, drafted idea or publisher has not actually run, label that segment as **conceptual** instead of claiming it was demonstrated. Keep the public release under [validation status](validation-status.md) until full acceptance evidence exists.
